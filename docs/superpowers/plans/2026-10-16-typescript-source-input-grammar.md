# TypeScript source-input grammar: implementation plan

Part of expanded #542. Design checkpoint only; no consumer production change is authorized before Root reviews this plan.

**Evidence.** Frozen observer `f624d992` over corrected union `0e3b8a7`: run [38966921173](https://github.com/rapiddweller/archkeel/actions/runs/38966921173), job `117195558561`. Existing policy selects 20 TypeScript sites: config 5, resolver 8, collector 7. The unchanged Dart policy selects another 31, addressed separately. No contract/baseline change produced this inventory.

**One owner.** Add `src/archkeel/analyzer/typescript/source_input.py` for the existing filename/suffix, source-category and specifier grammar. Move actual existing knowledge from the three consumers: `PathToken`, suffix recognition/order and shadow/source/declaration/runtime groups, `SourceKind`, `ModuleFormat`, relative/node/scoped/imports prefixes and the existing Node builtin-name catalog. Retain Snapshot I/O, TSConfig options/glob compilation in config; manifest/package decisions and lookup passes in resolve; fact publication in collect. This is a real shared input port, with no filesystem, parser-node or Core-policy authority.

**Interfaces.** Own plain `FileSuffix` and `SpecifierKind` enums. `classify_file(name: str) -> FileSuffix | None` distinguishes absent suffix from unsupported suffix; the absent case is an explicit enum value, never the fallback for an unsupported suffix. `split_file(name: str) -> FileParts | None` is the existing extension-rewrite boundary, with named `stem: str` and `suffix: FileSuffix | None`; no filename wrappers are created on property access. `classify_specifier(text: str) -> SpecifierInfo` returns a nominal kind plus named original/name/package data and directory-only state; exact dot/dotdot and dot-plus-slash forms remain distinguishable. Metadata on the owned suffix selects source category, declaration/runtime role, format hint and priority. Existing `PathToken.parse` remains the single segment/glob-token decoder.

Convert input once at each consuming operation's entry and pass the nominal result through its helpers; preserve the existing string queues, module/path identities and wire paths. No global cache, generic enum factory, lookup framework or per-access filename object. Genuine module/path data comparisons remain data operations. A real canonical input lexer may use a compiled grammar to return these nominal values; moving each old comparison into a bool wrapper, `startswith(Enum.value)`, renamed constants or regex-per-comparison is not this design.

**Compatibility.** Keep `resolve.ModuleFormat`, `resolve.SourceKind`, `resolve.Format` and moved `config.PathToken` as identity reexports, with actual enum declarations in one place. Snapshot bookkeeping uses canonical `archkeel.ir.facts.ResolutionRole`; preserve the legacy `Role` alias as that same owner and normalize valid legacy read-role values at the existing boundary, without a second role enum. Existing raw-name public helpers can remain thin compatibility entries to the same classifier. Preserve compiler mode defaults, lookup order, error/UNKNOWN reasons and filename identity. The parser's existing TS-versus-TSX filename decision must consume this owner's suffix result through a small adapter; `_Grammar` itself stays parser-owned.

Add supported/unsupported suffix, compound-declaration precedence, dotfile/case sensitivity, unknown-versus-absent suffix, exact relative marker versus prefix, trailing slash, `node:` scheme-only builtins, scoped names, imports aliases, outside paths and recursive-wildcard-tail cases. Verify ordinary path/module data and legacy aliases remain valid. Include the currently unobserved computed/dynamic suffix consumers (`config._supported/_shadowed`, `resolve._strip_extension/_mapped/_worker`), so passing only the 20 visible sites cannot leave duplicate suffix authority.

Update named component ports/requires and a small independent Target for the real enums, classifier results and SpecifierInfo/FileParts type fields. Add a whole-module source guard for the genuinely migrated owner; retain the three existing consumer guards without parser/form exceptions.
