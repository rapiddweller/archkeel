# AD-251: Catalog membership and source reads use canonical declarations

Catalog policy selects source declaration owners instead of copying values into Target contracts. `catalog_argument` binds a selected call's explicit argument to its formal parameter and checks exact string literals against unique parsed enum string values. Enum member expressions resolve through the existing canonical attribute-reference facts. Dynamic values, incomplete call identity, ambiguous declarations and missing catalogs remain UNKNOWN.

`catalog_use` checks each selected enum member, or one named member, for a real value or attribute reference in its declared source scope. An optional `target` and `parameter` pair also lets an exact, proven read operation count a bound string literal whose value matches a declared catalog entry. A literal at another call does not count. Dynamic actuals and unproven selected calls keep non-use UNKNOWN. Definitions, annotations, comments and docstrings do not count. `TYPE_CHECKING` reads count as syntactic reads. Exact and prefix scopes are explicit. Overlay selectors name separate enum declaration owners; arbitrary literal exceptions and project imports are not supported.

A complete eligible Python source scope with no selected read violates the rule. Missing, empty, partial or unsupported scopes remain UNKNOWN. Known argument violations remain visible with UNKNOWN facts. Receipts include selected catalog owners, call facts, reference facts, the contract and source identities. Runtime use, control-flow reachability, arbitrary constant propagation and dynamic catalog projection are outside this decision.

The focused synthetic tests cover string membership, enum references and no-use counterprobes. Full #613/#617 dependent alias and source-role checks remain pending the parent stack rebase.

A `catalog_argument` PASS also needs proof that no catalog enum member changes. Every member read in the whole snapshot, inside or outside the source, must be exactly one written argument of the selected operation, and that operation must make no call and no write. Any other read makes the result UNKNOWN. This covers each non-annotation read that the collector resolves to the enum owner, not only `Owner.MEMBER`: `Owner(value)` returns a member, so a call of the owner, a bare owner and an owner alias are escapes too (#731). The collector resolves the owner also through a module that imports it, such as `from .api import Owner` or `api.Owner`. It also records the reads inside a write target, such as `Owner(value).attr = x`, and the prefix of an attribute chain it does not resolve, such as `Owner.MEMBER.__dict__`. These two records change other results: `catalog_use` counts `Owner.MEMBER.value` as a use, `source_ownership` counts `NAME.attr = x` and `NAME.attr` as reads of `NAME`, and a prefix read on a continuation line keeps a `catalog_use` absence UNKNOWN because its one-line excerpt has no context. Known limits that still give PASS: a runtime consumer of an annotation, such as a model field `k: Owner` that converts a value to a member; a module reached through a string, such as `sys.modules[...]` or `importlib.import_module(...)`; and a selected operation that returns or changes its argument. An argument written as `name=value` is matched to the member read that starts its value; a wider value such as `member + 'x'` is not a member. `catalog_use` counts reads and keeps its result when a member escapes elsewhere.
