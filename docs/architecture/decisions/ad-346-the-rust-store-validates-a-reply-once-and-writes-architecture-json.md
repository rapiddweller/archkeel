# AD-346 The Rust store validates a reply once and writes architecture.json

**Decision.** The crate `native/store` (`archkeel-store`) is core v1, stage 1 of epic #880 (target
v2, WP4). The setting `ARCHKEEL_NATIVE_STORE=<path of the binary>` sends the reply of a TypeScript
collector through it. The setting is an opt-in, not the default.

1. **One process for one collection.** The collector runs as before. With `store` set,
   `ProcessCollector._decode_response` starts `archkeel-store` and sends frames on stdin
   (`session.rs`): `R` the reply, `B` and `D` digest requests, `W` the parts of the observation.
   The store keeps the records until the next observation (`ir/store_seam.py`).
2. **Validate once, typed.** The store decodes the reply in one pass from the zlib stream into
   the types of `archkeel-facts`, the envelope included (`facts/src/envelope.rs`), and keeps the
   typed `Reply`. It runs the generic checks of `validate_source_facts` with the same messages
   (`validate.rs`, `records.rs`, `bindings.rs`). They read a typed `View` of one record at a time
   (`view.rs`). It borrows the `Fields` that each data type of `archkeel-facts` gives
   (`facts/src/fields.rs`). The fields that only say "this is set" (`call_binding`, `property_members`, ...) describe what
   the store does not check yet. The store refuses a record that sets one. They shrink as the store ports those checks. The Python check does not validate the facts again. Until the PR after #941
   deletes the Python copies (WP4), the generic checks and the import projection of
   `evaluate.py:evaluate_source` (`stored.rs`) exist twice.
3. **Read-set.** The store answers with the read-set of `archkeel-facts` for each measured section
   (`seam.rs`); the gaps keep their wire form. Python builds its facts from it
   (`ir/readset_codec.py`).
4. **The store writes `architecture.json` 2.9.** Python sends its parts and names each stored
   record and evidence entry by its id (`ir/codec_store.py`). The store writes the canonical
   columnar bytes (`canonical.rs`), byte-equal to the Python writer. The Python writer refuses an
   observation while a store holds the collection.
5. **JSON edges.** Only two places see JSON: the parts of the shell (untyped observation
   records until the observation moves to the core, WP6); the Python byte formats of stage 1
   (`canonical.rs`, `pyrepr.rs`, `inventory.rs`, `pyjson.rs`), one stored record at a time
   (`stored.rs:saved`). No record is held as JSON, and the checks read no JSON. `check` and `validate --against` run without the store (`store_disabled`). The read-set frame is written twice, once
   to count its length, and is never buffered.
6. **Receipt digests.** The dependency proof hashes the Python `repr` of whole records, and the
   member inventory proof hashes their `asdict` JSON. The store writes both forms (`pyrepr.rs`,
   `inventory.rs`). `printable.rs` is generated by `tools/python_printable.py`.
7. **What the store refuses.** It reads only TypeScript replies of protocol 8 or 9. It refuses
   a resolution feature, a record kind or a field whose Python proof it does not port
   (`call_binding`, `numeric_operand`, ...), and any entry in `state`, `type_shapes`,
   `provider_bindings` or `candidate_evidence`. A refused reply is a protocol error, never a PASS.
8. **Packaging.** One crate holds the library and the binary entry. The host runs it as a
   subprocess (AD-317). The binary enters the wheel when the store becomes the default.
9. **Read-set width, checked by the corpus.** The rules read the imports section as one list, so each
   TypeScript import kind has the union of the import fields, with `symbols_known`. A TypeScript
   method keeps `async` (UML). `BindingData` holds `script_global`. A TypeScript reference and call
   drop `candidate_count`, `candidates_truncated` and `reason`; WP2's narrower list (only
   `targets`) changes verdicts, so it is rejected. The evidence stays whole: the HTML report shows
   its excerpt and lines (`render/html.py`). The e2e test fails when a rule reads a field that the
   read-set lacks: the bytes or the verdicts then differ from the Python path.

**Measured (x35, 910 files, macOS, median of 3).** Bytes and verdicts are equal on both paths.
Native collector: whole run 45.4 to 37.6 s, host peak 2 735 to 2 656 MiB. Python collector: whole
run 147.0 to 138.8 s, host peak 3 141 to 2 751 MiB. The store process peaks at about 2.3 GiB: it
copies each record into a `serde_json::Value` map. The host peak stays high: the read-set keeps
218 of 273 MB, and the check copies each record twice (`RawRecord`, then `Record`).

**Rejected.**
- **Store linked into the collector binary.** An external collector must reach the same store.
- **Two store runs (read-set, then write).** The second run decodes the reply again.
- **Python keeps the whole records for the digests.** That undoes the read-set.
- **A collector subclass for the CLI.** It adds a coupling name; one optional field does not.

**Limit.** The store checks only the generic part. It refuses Python and Dart replies and the
Python source proofs; it does not check them. `repr` follows Unicode 14.0 (Python 3.11): a code
point that a later Python assigns can change a digest. A `\d` of Python matches every decimal
digit; the reference test of `canonical.rs` reads only ASCII digits. Explore keeps the Python path,
because it reuses the facts of its first pass. The WP1 read lists are a lower bound: a field that
no corpus case reads can be missing. The next PR deletes the replaced Python code.

**Checked by** `native/store/src/*_tests.rs` (Python bytes and messages),
`tests/test_collector_native_store.py` (14 golden cases with both collectors, 53 demo variants,
the false-PASS probes on the store path) and `native/facts/src/record_tests.rs`.
