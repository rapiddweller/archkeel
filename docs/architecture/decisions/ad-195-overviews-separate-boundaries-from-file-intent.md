# AD-195 Overviews separate boundaries from file intent

When components are declared, the root diagram shows component boundaries and their
imports or declared requirements. Files and unassigned namespace groups are not peer
components. Component drill-down shows its recorded or independently declared code.

File inventories stay in Details. They do not create UML entities or inferred owners.
A visible Unassigned code entry opens the recorded modules without membership. Their
source identities, findings and UNKNOWN status remain unchanged. No code is dropped
from the report. Projects without component declarations retain their code overview.

Long root dependency chains use at most three layout bands, retaining rank order
within each band. A row does not declare an architecture layer.
Automatic Fit keeps at least 85 percent scale. Explicit Fit overview may shrink
further to show every card. Idle overview edges stay subdued; connected focus stays bright. Oversized diagrams remain pannable;
readability takes precedence over shrinking every label into the viewport. This does
not certify crossing-free routing for a complete dependency graph.

All three views use the same scene projector and renderer. Browser proof checks mixed
root input, inventory details, unassigned drill-down and unchanged report data.
