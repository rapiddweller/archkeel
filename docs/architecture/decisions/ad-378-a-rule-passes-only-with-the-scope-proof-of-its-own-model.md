# AD-378 A rule passes only with the scope proof of its own model

**Status.** Accepted. Epic #880, WP6 slice S4 (design WP6-0, section C; AD-363, AD-370, AD-372, AD-374).

**Decision.**
1. `Model::of` makes the scope state one time (`model/src/proof.rs`). A cause that the reference engine counts as a coverage failure or a diagnostic in every store-accepted profile is a fact (`Reason::NotComplete`, `Reason::Incomplete`): what the reply proves not seen (S1, S2); a pair gap that the drop rule keeps (`check/pair_gaps.py:59`, `:33`); a work tree that the host could not read (`check/observation.py:582`); a runtime below a `>=` requirement or without one (`check/runtime.py:35`, `:81`); a reply of an external collector without a pin (`check/observe.py:192`, `cli/observe.py:111`); a profile limit (`check/evaluation/rules.py:1285`, `crate_scope.py:133`); the layer metadata of `layer_order` (`rules.py:2130`, `:1990`); a rule side without subjects (`rules.py:1101`, `:902`, `:1018`, `:1066`, `ir/dependency.py:115`).
2. A cause that the core cannot read is a named gap (`Unsupported::ScopeProof(Part)`): a pair gap that the contract allows (the host drops it for one profile), a runtime requirement form other than `>=X`, a limit of some profiles only (`interface_boundary`, a symbol selector with `script-globals-v1`), a `forbidden_construct` without a module subject, a rule of another contract. A fact comes first.
3. `Scope::complete(rule)` gives the proof for one rule of the contract of the model: the scope state, then the receipt (`rules.py:2685`) and the dynamic imports that reach the rule (`rule_support.py:200`, `evaluate.py:1448`). A kind whose receipt the model does not know gives `Unsupported::Rule`, so S5 and S7 add their receipt here. The proof is branded, not `Clone`, and `pass` uses it up. This is `ir/decisions.py:760` `_rule_status` with `:1422` and `:907`, and `ir/coverage.py:26`.
4. The producer comes from the shell (`Settings::with_producer`); the default is external, which gives no PASS. The dual run reads it from `collector_argv` and `pinned`.
5. The frame of the core has `status`, `explained` (the reason of each UNKNOWN rule) and `violations` (the count of each FAIL rule). The status follows from the rows (AD-361 point 4). A FAIL rule without a violation, an UNKNOWN rule without a reason or a row without a rule is not written: exit 2 (L-23). The harness checks the same. The exit codes stay: the status is in the frame.
6. The three sections of the S4 design row stay unported and name what they need (`Porting::Unowned`).

**Reason.** A false PASS is the largest risk of the core (AD-363). Each cause of the reference engine is a check of its own, so a test can drop it one at a time.

**Rejected.** A profile table from the shell: the core cannot bind it to the reply, and a wrong table gives a false PASS. A proof per model only: the receipt and the dynamic imports belong to one rule. A port of the cycle part of the drop rule: a gap that it can drop stays a gap of one profile.

**Stricter than Python (all named).** An allowed pair gap: 2 PASS and 5 UNKNOWN rules of the corpus. `interface_boundary` in a TypeScript contract: 8 PASS rules (a probe and `s4/an-interface-boundary-is-a-limit-of-some-profiles`). A symbol selector with `script-globals-v1`: 4 PASS rules (`s4/a-symbol-selector-is-a-limit-of-some-profiles`). A runtime requirement that is not `>=X`, a `forbidden_construct` without a module subject: no corpus case. For the profiles that the store refuses, a `forbidden_construct` selector, the Python profile limits and an SDK target of the Dart profile give UNKNOWN where Python can PASS.

**Limit.** Parity holds only for replies that the store accepts (TypeScript, Rust). The Python collector writes the only dynamic import limits; the Rust tests check them. A Python reply also needs the uncollected rule families (`evaluate.py:937`), which the core does not check: `native/model/src/edges_tests.rs` fails when the store accepts a third profile. The reply of the honest external collector is not compressed, so its two s4 cases name the refused reply. The core does not re-read the contract file that `layer_order` binds (`observation.py` `_layer_order_evidence`). #1059 item 3 (a brand on `ModuleId`) is not done: the rule check of point 3 binds the rule, not the ids.

**Corpus (587 cases, the four decided kinds).** Both PASS 156 (before 0), both FAIL 33 (33), both UNKNOWN 130 (83). Core named where Python decides 1 091 (inside tree, refused reply, baseline, 14 parts of the proof); core named where Python gives UNKNOWN 144; core decides where Python differs 0. The 94 rule lines and 555 section lines named `slice S4` before are 0: the sections name what they need, and 10 lines (19 rules) name a part of the proof.

**Tests.** `native/eval/src/scope_tests.rs` (each cause one at a time), `receipt_tests.rs`, `native/model/src/subjects_tests.rs`, the doctests of `native/model/src/scope.rs` and of the crate `native/model-barrier` (15 attempts, each with a twin that compiles), `native/core/src/status_tests.rs`, `engine_tests.rs`, `dual_run_tests.rs`; `tests/test_native_core.py` (`test_the_scope_proof_gives_the_verdict_of_python_or_an_exact_name_on_every_case`), `tests/test_dual_run_shell.py` (`test_a_frame_status_follows_from_its_rows_and_each_status_has_its_row`); the 19 cases `s4/*`.
