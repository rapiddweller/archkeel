# AD-734 The Explorer has one view state

**Status.** Accepted. Part of #880, #1451 (Wave 2, E1). Step 1 (decisions 1 to 4) is structural: no visible change. Steps 2 and 3 (decisions 5 to 8) are visible: Back goes back one level, and a link keeps Details, the drawer and the perspective. E2 (decision 9) is visible: the theme that the user chose stays after Back. E3 (decision 10) is visible: up one level, the Escape ladder, and a relayout that keeps the selection. E4 (decision 11) is visible: the page of a part names its system and links up; a system page names its title. E5 (decision 12) deletes the unreachable non-atlas branch (owner approval 2026-11-17).

**Reason.** The Explorer (`native/report/assets/explorer/flow.js`, `report-canvas.js`) kept its view state in loose variables: the view, the path of levels, the content (components or modules), the selected box, the selected import cell and module, the question hint, the open Details, the open drawer, overlay and popover, the perspective, the pinned tag, the theme and the expanded mode. Each handler changed some of them and then drew. No one place said what the state is, so no test or agent could read it, and the URL, the history and the drawn page could disagree.

**Decision.**
1. One object `S` in `flow.js` holds the view state: `view`, `path`, `content`, `selection`, `cell`, `module`, `hint`, `allHints`, `details`, `explore`, and the presentation choices of `report-canvas.js` (`perspective`, `pinnedTag`, `drawer`, `overlay`, `pop`), `theme` and `expanded`.
2. A user action is one `dispatch(action)`. Each `action.type` is one case of one `switch`; an unknown type throws. The DOM handles of a drawer, an overlay or a popover stay in `report-canvas.js`; their names are in `S`.
3. `report-canvas.js` reads `ArchkeelFlow.S` and changes it only through `ArchkeelFlow.dispatch({type: "present", ...})`. Their effects (badges, drawers) stay in `report-canvas.js`.
4. `S.theme` follows the `data-theme` of the page, also when the header switch sets it.
5. `toQuery(S)` writes the URL of a state and `fromQuery(query)` reads the state of a URL: `scope`, `content`, `view`, `perspective`, `selected`, `cell`, `details`, `drawer`. A default is left out: the language perspective, Details that follow the selection (open with a selected box or cell, closed without), no drawer. `toQuery(fromQuery(q))` is `q` for each query that `toQuery` writes. `report-canvas.js` writes no URL of its own.
6. `data-state` on the Explorer holds the state as JSON (view, scope, path, content, selection, edge, module, cell, hint, details, drawer, overlay, pop, perspective, pinned tag, theme, expanded, notice). `ArchkeelFlow.state()` returns the same fields, and `ArchkeelFlow.dispatch`, `toQuery` and `fromQuery` are public to the page.
7. History: a navigation (open a level, go up, a crumb, set the view, set the content, open a module at another level) adds a history entry. Any other change (a selection, a cell, Details, the drawer, the perspective, the theme) replaces the current entry. So Back goes back one level, not one click.
8. A deep link restores the selection, Details, the drawer and the perspective. Details stay open at the start when the link selects a box or a cell (the report no longer closes them at the start).
9. `archkeel-theme.js` is the one owner of the theme (the header switch, localStorage, the OS default). The Explorer follows `data-theme` into `S.theme`, writes no theme into a URL or the history, and reads none from a URL. A `setTheme` action presses the header button of the owner. Before, Back set the theme of the old URL again, so the page turned dark while the header still said Light.
10. Up one level is derived from `S.path` (the level that you leave is selected in its parent); the Explorer keeps no second history of its own. `Alt+ArrowUp` goes up; the current crumb has `aria-current="page"`, every crumb has its full name as a title, and the crumbs above the current one shorten first, so the current crumb stays whole in a narrow bar. `relayout` lays out the same state again: fullscreen and the key of the current view keep the selection and add no history entry; another view keeps a selection that it shows. Details come from `S.details` only, also for a route notice. Escape is one ladder: overlay, popover, drawer, expanded, selection (the selection with its module, cell and hint), one step per key.
11. The root of the Explorer comes from the core (`navigation` of the payload), no longer from the gallery: a system page names the title of its system (it said "System"); the page of one part, written with `archkeel report --part-of <system document> --system-href <url>`, reads "<part> of <system>" with the system as a link to `url`. The core reads both titles from the system document and refuses a document that is no system document or names no part with this configuration. The link is an input of the page: the frame does not carry it. The gallery passes both options for each part page; its page bar stays.
12. The Explorer has one branch, the atlas. Every payload of the core has an atlas (`atlas::payload` is its one maker), so the sidecar and graph branch of `flow.js` (`SIDECAR`, the sidecar parts of `readRoute` and `syncRoute`, `renderSidecar`, `renderArchitectureGraph` with its inspector and table views, `viewStates` and the navigation history, `scopeNotice`, card drag and double tap) and the `!A` branches of `report-canvas.js` are deleted, with the helpers that only they called. `flow.js` refuses a payload without an atlas by name.

**Rejected.** A state library or a build step for the Explorer (the scripts are plain, hashed files of the page). One state per script (the URL needs all of it).

**Tests.** `tests/test_report_explorer_state.py` drives the page in a headless Chrome (harness `tests/explorer_support.py`): the start level, Back, a deep link, a click, a view switch, Details, a crumb, Escape, a perspective, a matrix cell, and opening a module. They pass before and after step 1. Steps 2 and 3 add tests that failed first: Back after two selections goes back one level, a deep link restores Details, the drawer and the perspective, and the URL of a state gives the same state back. E2 adds two that failed first: Back keeps the chosen theme, and a reload keeps it with no theme in the URL. E3 adds five that failed first: `Alt+ArrowUp` and the current crumb, the whole current crumb in fullscreen, fullscreen and the current view key keep the selection, the Escape ladder, and Details of a route notice. E4 adds the crumb of a part page and its link (browser), the payload of a part page and of a system page (`html_system_tests.rs`), and the refusals of `--part-of` (`tests/test_cli_report_part_of.py`). E5 adds `every_explorer_payload_has_an_atlas` (`html_system_tests.rs`) and `test_each_explorer_payload_has_an_atlas` (the written pages).
