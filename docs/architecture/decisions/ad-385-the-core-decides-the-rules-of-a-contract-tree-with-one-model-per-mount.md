# AD-385 The core decides the rules of a contract tree with one model per mount

**Status.** Accepted. Epic #880, WP6 contract lane. It replaces points 5 and 8 of [AD-379](ad-379-the-core-asks-the-shell-for-the-inside-contracts-and-decides-the-root-rules-of-a-tree.md) for the nine decided kinds of [AD-370](ad-370-the-core-decides-the-rule-kinds-of-modules-and-ownership.md), [AD-372](ad-372-the-core-projects-the-edges-and-decides-the-external-rule-kinds.md) and [AD-380](ad-380-the-core-decides-the-direction-rule-kinds.md).

**Decision.**
1. `archkeel_model::ModelTree::tree` makes one `Model` for each contract of an assembled tree: the root, then each mount in the order of the walk. Only the model makes one (attempts 25 to 27 of `native/model-barrier`). The tree assembly marks each inside contract with a private field (`Contract::mount`, attempt 28: no crate clears it), and `Model::of` refuses a marked contract (`Unsupported::InsideRule`): the crate order puts the contract crate below the model, so a type cannot stop the call, and the refusal is at run time. The domain and the owner table of a mount hold only its own modules.
2. A mount (`evaluate.py` `_inside_rule_results`): its owner is the root or the mount whose parent key is its owner key; its parent is the component of that id in the clipped contract of the owner (`_inside_parent_component`); its domain is each module of the domain of the owner that the parent owns; `archkeel_contract::policy::clip_inside` clips each claim to the parent (`_inside_source_domain`). Rule ids and component ids stay scoped (`parent:id`, AD-366), so each violation id and evidence id is the id of Python.
3. Each kind reads, in the model of its contract: the domain for its source side, its receipt and its dynamic imports (`model.holds`, `model.selects`); every module for a target side and for the internal roots of `complete_external_scope`; the clipped components for its owners. `root_layout` reads the packages below the packages of the parent (`source_roots`). `allowed_dependency` stays a DECLARATION.
4. The models share one scope state (`proof::state` with `MountFacts`): a cut claim (`Cause::InsideSourceDomain`), a profile limit of a mount and a mount rule without subjects in its domain hold back each PASS of the tree, as each is a coverage failure of the whole run in Python. A tree keeps every pair gap (`drop_allowed_pair_gaps` `has_insides`), and each gap is a cause of that one state: the gap scope of [AD-384](ad-384-the-core-decides-the-cycle-rules-and-scopes-each-pair-gap-to-the-rules-it-can-change.md) applies only to a model without mounts, so no rule reading of one mount releases a rule of any model of the tree (`a_gap_inside_one_mount_holds_its_rule_and_releases_no_rule_of_another_mount`).
5. A PASS needs `Scope::complete` of the model whose contract holds the rule: the proof of the root or of another mount gives `Part::ForeignRule`. The core checks each PASS against the model of its outcome, and names a PASS of a tree whose models do not hold every mount (`Unsupported::TreeScope`, the second line).
6. The report (`archkeel_report::build`, AD-381) takes the `ModelTree`. Each rule row is checked against the model whose contract holds its rule (`ModelTree::model_of`): a PASS of another mount or of the root is `ForeignPass`. A run PASS needs `ModelTree::pass_run`: each decision is a PASS of one model, and each model gives its own run proof (`Scope::run_complete`) over its own rules; `RunPass` names the serial of each model, and the run PASS of a tree has no second maker or check (`RunPass::of` reads one model). So a named, missing or failing rule of any mount holds the run back, and a refused tree has no models and no PASS.
7. The run status is the status of AD-378 over the rules of every contract of the tree and the one scope state. A tree with an issue, a missing file or a reply that the store refuses names each rule of the tree, as AD-379 does.

**Named, not decided (each a gap with its own name).**
- An inside `layer_order` rule: its row and its receipt cite the inside contract file (`Part::MountedLayerOrder`). 1 rule of the corpus.
- An inside `complete_requires` without a violation: the scan roots or the dependency scope proof of AD-380 (`Part::ScanRoots`, `Part::ScopedRequires`), as at the root. 20 rules.
- A mount whose parent is not in the contract of its owner (`Part::MountParent`). The assembly makes it impossible today; Python uses a parent without packages.
- A child of a `root_layout` rule of a mount that only a package record cites: `Reason::UncitedChild`, as at the root.
- A root rule whose id is the scoped id of a mount rule (`domain:SAME` beside the rule `SAME` of the mount `domain`): Python merges the two rules into one; the core refuses the tree by name (`generated declaration ID collision`). Test: `a_root_rule_with_the_scoped_id_of_a_mount_rule_refuses_the_tree`.

**Reason.** 299 of the 654 corpus cases have a contract tree, with 7 775 rules of the nine kinds. Python clips each inside contract to its parent and folds its failures into the coverage of the whole run, so the root rules depend on the mounts and the inside rules on their domain. One model per contract gives each rule the proof of its own scope; the shared state keeps the fold.

**Rejected.** One model with a list of domains: a rule could read the domain of another mount, and the proof would not name the subtree. A domain filter in the evaluator only: the scope proof and the receipt would read the whole reply. A guessed source of the inside contract file for `layer_order`: no corpus case proves its evidence id.

**Limit.** Parity holds only for replies that the store accepts (TypeScript, Rust): 7 206 rules of the 299 cases name the refused reply, and 210 a baseline. The available set of the owner is redundant with the clipped parent in Python; the core keeps it, and no test can tell them apart (faults F08 and F25 of the PR).

**Corpus (654 cases, the nine kinds, with AD-384 on `main`).** Of the 7 775 tree rules, 15 are decided before AD-384 and this record, and 188 here (117 PASS, 25 FAIL, 45 UNKNOWN, 1 DECLARATION). The rest is named: 7 206 refused reply, 210 baseline, 145 missing or refused tree, 25 dependency scope proof, 1 inside `layer_order` file. A tree rule where the core decides and Python differs: 0; the 21 core PASS over a Python UNKNOWN of the corpus are the pair-gap rules of AD-384 in cases without a tree. Core run status PASS or FAIL where Python differs: 0. The 9 `inside/*` cases equal Python on 105 of 106 rules with their violation rows; the other names the inside `layer_order` file.

**Size (release build).** 1 000 sibling mounts with 2 000 modules: 0.17 to 0.33 s and 54 MiB (`main`, which decides none of these rules: 0.43 s and 40 MiB); 500 mounts: 0.05 s and 29 MiB (`main` 22 MiB), so the memory grows with the mounts. The largest corpus case (`rust/native`): 0.04 s on both, 22 and 23 MiB. The core reads at most 1 024 inside contracts (AD-379).
