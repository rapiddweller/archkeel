# AD-1061 The self-check is compared with its base commit, beside the pins

**Status.** Accepted. Owner decision of 2026-11-23: delete the pins and compare the self-check result of a PR with the result of the same run on its base commit. This is stage 1 and 2 of 3. Supersedes in part AD-672, AD-733, AD-944 and AD-945. Amends AD-357, AD-382, AD-432, AD-478, AD-674 (point 1) and AD-736 (point 8).

**Reason.** `native/expected-gaps.json` holds 18,389 gaps (92,050 lines). `native/expected-growth.json` holds 165,553 lines for about 6 distinct reasons. 86 commits changed the pin in 14 days. No person reads these files. The aim of the pin is "no growth". The base result tests that aim and stores nothing in the repository.

**Decision.**
1. **Base result.** Main CI saves the condensed result of `make self-validate-native` as `test-artifacts/selfcheck/base.json` in the cache key `selfcheck-v1-<os>-<sha>`. The gate writes its own result to `result.json`; main CI copies it to `base.json` only when the gate ran in that job. It keeps the gaps (kind, subjects, reason), the rule statuses, the number of scanned files (`frame.self_test.reply.files`), the UNKNOWN reason kinds, the violations, the exit code, the sha and the native tree. The size is 5 MB, and 125 KB compressed. Main CI saves it also when other jobs are red.
2. **Where the base comes from.** Base is the merge base of `PR_BASE` and HEAD. Each workflow deletes `result.json` and `base.json` before the restore. The gate fails when git tracks any file under `test-artifacts/selfcheck/`, so a PR cannot bring its own base. The PR gate restores the key of `pull_request.base.sha` to `base.json`, a path that nothing else writes. A miss runs the same check in a git worktree of the base commit. It reuses the core of this tree when `native/` is the same. Else it builds the core of the base commit. The gate never skips. It fails with the reason when the computation fails. A red base commit stays valid. A local run uses `PR_BASE` (default `origin/main`) or `BASE_RESULT=<file>`. Main CI uses `HEAD~1`.
3. **Tool.** `tools/self_check_diff.py <base> <pr>` names each grown item. Growth is a new gap (a multiset compare), a new UNKNOWN reason kind, a rule with a worse status (PASS < UNKNOWN < FAIL), a rule that is gone (`rule removed`), or a scan of fewer files (`scope shrank: files A -> B`). Removals do not offset additions. A reworded reason shows as one new and one removed gap. The PR result must have no refusal, no FAIL and no violation, and the exit code that its statuses give. A result with no frame or no rules is unusable. These checks need no base and no approval can pass them.
4. **Approval.** Growth passes only with the label `ratchet-lead` and the PR text line `Ratchet growth: <N> items: <reason>`, where N is the printed count. A base that is missing, corrupt, refused or for another commit compares as an empty base. It passes only with the same approval. The line must be a plain line of the PR text: not in a code block, a quote or an HTML comment. It has ASCII digits, no leading zero, a reason of 10 characters or more, and it is the only such line. The PR gate reads the label and the text with `gh api`, so a re-run sees a later label. Only a boolean (`RATCHET_LABELED`) reaches `GITHUB_ENV`. The workflow runs again on `labeled`, `unlabeled` and `edited`.
5. **Beside the pins.** `make self-validate-native` runs the pin gate and then the new comparison. The new comparison fails the PR gate and a local run. Main CI only reports it, because main CI cannot see the label of the merged PR. A different verdict of the two gates prints one line `GATE DISAGREEMENT` and goes to the job summary. The pin gate stays authoritative for the verdict of main CI.
6. **Nightly.** Full verification builds the release core and runs the check with `--no-compare`. It then compares the result with the gate-profile result of the same commit (`self_check_diff.py same`). A difference fails the job. This checks AD-754 and determinism. When no gate-profile result is cached, it prints that it compared nothing.

**Stays until stage 3.** The pin gate, `native/expected-gaps.json`, `native/expected-growth.json`, the shell pin and its growth file, `tools/native_expected.py` (AD-672, AD-733, AD-944 and AD-945 apply to it), `RATCHET_FILES` and `ratchet_removal_unapproved` (AD-736, point 8). Stage 3 deletes them. Then the stale-entry rule (AD-733) and the pin growth file (AD-672, point 2) end. The count rule of AD-944 and AD-945 moves to this tool (point 3). The shell check needs only exit 0.

**Amends.** AD-357 and AD-382: the accepted pair gaps and the crate chain are no longer listed in a pin; the multiset rule stays. AD-432 and AD-478: the self-check compares with the base result. AD-674 point 1: a label or text change runs the PR gate again, and main CI saves the result. AD-736 point 8: the guard for removals ends in stage 3.

**Rejected.** A count only: 5 removed gaps hide 5 new gaps (AD-672). A rename map for reworded reasons: it is a new stored file. A local base cache: a developer uses `BASE_RESULT`. A required new comparison in main CI: it cannot see the approval.

**Limit.** The base cache of a commit is missing when its main run was dropped (AD-674). The time of a miss is an estimate, not measured in CI: about 10 s locally when `native/` is the same. When `native/` changed, the gate builds the core of the base commit cold inside the 15-minute job (75 s on 4 local cores). A growth that merges by skew prints one `GATE DISAGREEMENT` in main CI and is then the new base. A violation has no approval path. A PR that deletes scanned files needs the approval too. The approval binds the count, not the items: a later push can swap N approved gaps for N other gaps. The list is in the job log. The owner decides later whether a digest is needed. If the new gate has a bug, a PR can escape it only by editing `pr-gate.yml` or the `Makefile`, because a `pull_request` run uses the workflow of the PR. The list of accepted gaps is no longer in the repository.

**Tests.** `tests/test_self_check_diff.py` (the cases, each run on real results of the core), `tests/test_self_check_gate.py` (a committed base is red), the fixture `scan-shrank.json`, `tests/test_make_self_check.py`.
