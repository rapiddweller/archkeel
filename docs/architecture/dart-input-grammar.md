# Dart input grammar boundaries

The existing syntax owner decodes name privacy through `Visibility.from_name`.
Only the final written qualified-name segment determines that value. Immutable
`ResolvedBinding.visibility` is derived at ingress; the public seven positional
or keyword constructor arguments remain unchanged, including replace(name=...).
Later resolver accessibility checks read the nominal field.

The parser owns nested-comment delimiters and its existing formatting lexemes.
Const constructors come from actual syntax kinds, not identifier prefixes.
Resolver receiver classification reuses existing computed and exact CALL facts,
without a new Site state or a punctuation-based claim of construction.

Snapshot owns source-filename and pubspec line grammar. Selected malformed
.dart filenames still reach the existing module validation path. Resolver
retains URI schemes and balanced type tokens, and uses semantic path APIs for
absolute/root containment decisions. No new source module, parser framework,
filesystem authority or Dart-project construct capability is introduced.

The existing Python implementation guards cover all five Dart owner modules.
Native verification explicitly overlays the frozen prefix-predicate observer;
it does not claim that earlier collectors already observed those controls.
Existing Compass, SDK-free, directive, partial-UML and false-positive assertions
remain the behavior oracle; no UNKNOWN or analysis budget is concealed.
