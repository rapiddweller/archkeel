Architecture atlas · target vs. observed

Warum so? (Notizen zum Entwurf)
  • Das Target ist der Bezugsrahmen. Das As-is wird immer darin gezeigt: gleiche Kartenpositionen, und die Modul-Matrix ist nach den Target-Komponenten gruppiert. So fällt auf, was nicht in seinen Rahmen passt.
  • Erkunden statt Urteil. Unter der Karte steht pro Ebene die Modul-Matrix (Zeile importiert Spalte). Ein Hub ist eine dichte Spalte. Ein Fremdkörper ist ein Punkt außerhalb seines Blocks, rot, wenn das Target ihn nicht erlaubt. Die Matrix skaliert auf 492 Module (CE), ein Graph nicht.
  • Hinweise sind Fragen. Sie entstehen deterministisch aus Zählungen im Report: nur von einer fremden Komponente genutzt, Hub, auffällig schwer, ohne Owner. Archkeel urteilt nicht; der Mensch entscheidet. „Copy as question“ übergibt die Frage samt Beleg an den Agenten. Die Entscheidung landet im Contract und wird ab dann geprüft.
  • Gewicht sichtbar. In As-is tragen Karten „Module · Symbole“. Ungleichgewicht (z. B. check gegenüber host) springt ins Auge.
  • Wer hat entschieden? Agenten-Entscheidungen sind markiert und gezählt. In CE stammen 632 von 646 Entscheidungen von Agenten. Erkunden ist dort die Stichprobe des Architekten.
  • Drei Linsen, eine Karte: Target zeigt nur Deklarationen, As-is beobachtete Imports (Strichstärke = Anzahl), Diff nur Abweichungen (gestrichelt = erlaubt, ungenutzt; rot = genutzt, nicht erlaubt; gelber/roter Rand = Regeln UNKNOWN/FAIL).
